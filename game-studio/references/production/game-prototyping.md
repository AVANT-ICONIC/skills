# Optional PROTOTYPE/BUILD protocol

Authority: explicit instruction to implement in a specified project or a clearly authorized disposable workspace. Brainstorming, REVIEW and RESCUE do not permit code writes by themselves.

1. Preserve existing user state, read README/AGENTS/working tree/branch, inspect relevant input/state/rules before touching code. Choose the smallest coherent playable vertical slice and an isolated branch or temporary workspace where possible.
2. Lock the *fun hypothesis* and design two real consequences of one repeated physical input. Include controls (key/mouse/touch), visible result, state mutation, resource or time cost, failure and recovery. “Pretty animated mock” without consequential input is not playable proof.
3. Implement one complete short loop end-to-end, preferably in the project's existing framework. Stub optional audio/art/economy, but do not stub the core decision itself. Keep UI, logic and feedback connected; avoid building unrelated systems to create the appearance of scope.
4. Run actual tests or launch and interact with the artifact. Check initial flow, both choices, invalid action, loss/retry, a second cycle, inputs on intended devices, and state after progression. If a renderer isn't available, mark visual behavior NOT_EVALUATED and leave precise reproduction steps.
5. Record the baseline and best tested candidate. CODE → CHECK real behavior → FIX → CHECK → POLISH → CHECK; don't hide a regression because the final screen looks more refined. For performance/multiplayer claims, demand representative measurements, not console absence of errors.
6. Distinguish source-build success, automated input assertions, simulated agent play, real human comprehension and enjoyment. Only genuine human reports/behavior support claims about actual people enjoying it.

**Stop rule:** A user-authorized minimal prototype ends when its hypothesis is testable. Do not automatically progress to app-store publishing, multiplayer backend, purchases, or a full production phase.
