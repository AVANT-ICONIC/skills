# Canonical shared geometry policy

Version: geometry-policy/1.

## L1 Symbol geometry

Use mathematically declared circle, ellipse, Bézier, affine transforms, φ relationships and provenance. Normal black symbol mode requires one region joined by positive-width connections, not a tangent point. An explicit multi-part mode may allow separated pieces. Black on white has real filled-region semantics including evenodd/nonzero; current cutouts are painted white and are **not** generally alpha-transparent. Arbitrary curved Booleans and unsupported XML markup return UNSUPPORTED. No decorative circle overlay proves original golden construction.

## L2 Compositional regions

Generate semantic nested region trees with named axes, negative-space reports, alignment, focal metadata and true family structural diversity. φ-derived ratios attach to actual nominated dimensions and carry residuals and provenance. Diagonal canon is not golden angle. Locked references and user-specified structure outrank diversity. Content, action visibility and mobile reading order override soft ratios with recorded exceptions.

## L3 Standalone auditing

The auditor is standalone. Exact source relationships are `declared`; post-hoc matches are `inferred`. Output actual fields, units, source/candidate SHA-256, positive/negative topology, hard-rule failures, honest UNVERIFIED or NOT_EVALUATED capabilities and reversible candidate comparisons. Reject loss of a counter or worsening hard residual. Never overwrite an approved mark or treat synthetic refinement as owner approval.

## L4 Responsive UI

Primitive and semantic CSS tokens include `base × phi^power`, bounds, resolved values and exception ledger. Functional legibility, hit targets, proper container-query eligibility and 200% text reflow override ideal proportions. Test actual 320/390/768/1280/1920 rendered content and interactions when available. A CSS string is not an observed pixel value; no blanket accessibility certification.

## L5 Design grammar and evidence

Grammar rules have typed split/align/focal/safeZone/rhythm/vary relationships and explicit source/evidence category. Three options require structurally different trees, not just different colors; a fixed-reference task must never randomize the locked layout. Keep mathematical correctness, real pixel survival, optical/human judgment and independent comparative uplift as distinct verification channels. No universal beauty score.

## Runtime / privacy

Use offline Node builtins and optional free locally installed renderer. Capability probe first; do not claim inaccessible tests passed. Do not access credentials or paid APIs. The `gauntlet-loop` skill may be used alongside this one, but this skill neither modifies nor depends on it. An environment without Node or a renderer must state its capability limits and hand off precise local steps, never a fabricated run log.
