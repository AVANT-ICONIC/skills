# Writing, research, analysis and data

Use the lightest meaningful checks. Small ordinary replies should not generate evidence theater.

## Writing
- Check full requested purpose, exact constraints, audience, tone, completeness and internal consistency.
- Identify repetition, unsupported claims, weak logic, contradictory definitions and missing essential details. Repair and reread full latest draft, not merely changed paragraph.
- Exact-output or copyable artifacts must not acquire QA metadata, assistant personality or tool receipts inside the deliverable.

## Research
- Prefer direct/current primary source where material and available; verify publication vs event dates, quoted findings, numeric units, evidence quality and source applicability.
- Challenge the strongest claim with a disconfirming source, counterexample or independent calculation where feasible. Distinguish fact, hypothesis, estimate and unresolved uncertainty.
- Never create sources, citations, URL claims or claimed inspections without actual retrieval.
- If material source access is blocked, narrow the conclusion or label NOT_EVALUATED; don't confidently substitute recalled facts.

## Data
- Audit source grain/freshness, missingness, duplicates, joins, definitions, sign conventions and calculation traceability.
- Recompute critical figures independently or with an alternate method if feasible. Do not treat a chart as correct just because code rendered.

## Single-agent adversarial pass
Ask: What explicit user constraint did I miss? What claim can I falsify? What has been assumed from prior output? What new problem did my last revision introduce? Use the answers to make actual improvements, not stage roleplay.
